# 飞行棋主题包 · 写包规范

> 所有新增/扩写的任务卡都按这份规范写。规范里的每一条都有对应的自动化断言，
> 写完跑 `npm run check` 就知道有没有踩线。

## 一、文件格式

一个包 = 一个 `src/data/themes/` 下的 `.ts` 文件，导出 `Theme` 对象（不带 `mode`，`mode` 由 `index.ts` 统一注入）：

```ts
import { Theme } from '../../types';

const bondIntro: Omit<Theme, 'mode'> = {
  id: 'bond-intro',
  name: '束缚入门',
  desc: '先说好边界 · 再试第一次',
  audience: 'common',
  tasks: [
    "[both][Q] 你对「被蒙眼」这件事的第一反应是什么？会不会紧张？",
    "[both] 先和对方约好一个停止词，然后才继续下一条。",
  ],
  actionStates: [
    "[M] 每次动作前先确认对方的呼吸",
    "[F] 每次动作前先确认对方的呼吸",
    "[both] 每次动作前先确认对方的呼吸",
  ],
  conditionStates: [
    "[M] 安全词一旦说出口，立刻停",
    "[F] 安全词一旦说出口，立刻停",
    "[both] 安全词一旦说出口，立刻停",
  ]
};

export default bondIntro;
```

- 文件名：情侣包 `coupleXxx.ts`，普通包 `normalXxx.ts`
- 变量名 = `id` 的驼峰形式；`export default` 变量名
- `id` 全局唯一，kebab-case
- `name` / `desc` 会显示在选包弹窗里

## 二、标签约定

标签写在任务正文**开头**，方括号紧挨着，可叠加：

| 标签 | 含义 | 什么时候用 |
|---|---|---|
| `[M]` | 只由男方执行 | 任务只有一方能做，或一方主导 |
| `[F]` | 只由女方执行 | 同上 |
| `[both]` | 双方都能执行（默认） | 两人对称的任务 |
| `[Q]` | 提问型：执行者要**回答**一个问题 | 有真实问题要问出口 |
| `[R]` | 奖励向 | **只有「奖惩卡池」用**，其它包一律不标 |
| `[H]` | 惩罚向 | 同上 |

没有 `[M]`/`[F]`/`[both]` 的任务按「双方都能执行」处理；没有 `[Q]` 的任务按「动作型」处理。

**烈度由包决定，不由标签调节。** 一个包只放一个烈度档，转换包一律不标 `[R]`/`[H]`。

## 三、人称规则

任务卡上：

- **「你」= 执行者**（运行期会替换成执行者的名字）
- **「对方」= 伴侣**（运行期会替换成伴侣的名字）

所以：

- 写「你」的时候，指的是**做这件事的人**
- 写「对方」的时候，指的是**另一个人**
- 替换**不区分引号内外**，引号里的「你」同样会被替换

### 禁止出现

以下词一律不能出现在题面里（会被自动化断言拦下）：

```
老公  老婆  妻子  丈夫  男生  女生
```

另有两个包级别的禁止名单（沉浸类包）：`甜甜` `实习生` `学长` `班主任` —— 这类**当场在场**的第三方角色在两人局里放不下。

### 「让对方对你说」的写法

对方要念台词给你听时，写成：

```
"[both] 让对方对你说：「今天你很听话。」说完你要回答：你觉得对方最想让你记住哪句？"
```

注意：台词里的「你」指的是**执行者**（对方在对你说话），所以台词里**不要**出现「你」。

### 需要角色扮演的包

「情境扮演」这类包里，「对方」不是伴侣而是**刚认识的角色**。这类包沿用它原有的「男生/女生 + 他/她」写法，与包内已有任务保持一致，不要硬改成「对方」。

### 第三方角色

场景设定里提到「想象」「梦里」「角色扮演中有第三个人」是可以的 —— 那不是真的在场。
但「当场有第三个人」不行（两人局放不下）。

## 四、执行方池

包里每条任务的执行方标签决定它进谁的池子：

- 标 `[M]` → 进男方的池
- 标 `[F]` → 进女方的池
- 标 `[both]` → 两边都进

包的「执行方池」= 实际能被用到的题数：

```
audience = 'male'   → 女方的池大小   （男方选包，女方执行）
audience = 'female' → 男方的池大小
audience = 'common' → 两边池的较小值
```

一局实际抽多少题：`scripts/sim-play.ts` 实测（真实棋盘 + 骰子 + 抽题逻辑，每包 200 局）
—— **一局约 17.1 个任务，两人分摊 → 单方每局约 8.6 个**。

按单方池算能撑几局不重复 ≈ 池 ÷ 8.6：

| 池大小 | 够几局不重复 |
|---|---|
| ≥ 9 | 一局 |
| ≥ 18 | 两局 |
| ≥ 26 | 三局 |
| ≥ 35 | 四局 |

**新写/补写的任务要保证包的执行方池 ≥ 35**（四局不重复）。
`[both]` 任务两边同时进池，补池效率最高 —— 优先写 `[both]`。

## 五、烈度

一个包 = 一个烈度档。补写任务时，**必须和包里已有的任务同一烈度**，不能往包里混进明显更轻或更重的。

各包的档位参照（写在包文件头部的注释里）：

| 包 | 档位 |
|---|---|
| 心动序章 / 甜蜜日常 / 暧昧升温 | 入门到推进 |
| 干柴烈火 / 极度诱惑 | 中段 |
| 灵肉合一 / 众目之下 / 客厅禁区 | 中高到高 |
| 底线条（底线之后 / 戏中失控 / 枷锁深处 / 越界癖好） | 高 |
| 束缚试探 / 癖好清单 / 主控调教 / 女王支配 / 契约情侣 | 硬（硬是「入门层」的意思：第一次，但不轻） |

新写的**入门层**包（束缚入门 / 调教入门 / 禁忌入门）是「第一次」，比「硬」档**轻一档**：
重点是**协商、试探、边界、停止词**，不写露骨细节。

## 六、状态池

每个包都要有 `actionStates` 和 `conditionStates`，各 3 条：

```ts
actionStates: [
  "[M] 每次动作前先确认对方的呼吸",
  "[F] 每次动作前先确认对方的呼吸",
  "[both] 每次动作前先确认对方的呼吸"
],
conditionStates: [
  "[M] 安全词一旦说出口，立刻停",
  "[F] 安全词一旦说出口，立刻停",
  "[both] 安全词一旦说出口，立刻停"
]
```

- `actionStates` = 触发某个动作时贴的状态文案
- `conditionStates` = 触发某个条件时贴的状态文案
- 状态池里同样不能出现禁止词

## 七、命名与 UI 中性

`name` / `desc` 会显示在选包弹窗、设置页等界面上。

- 不要出现任何**模式名**：情侣、普通、题库、剧场
- 不要出现**空间名**：书房
- 也不要出现「双人版」「成人版」这类暗示

## 八、自检清单

写完一个包，逐条自查：

- [ ] 任务正文里没有 `老公 老婆 妻子 丈夫 男生 女生`
- [ ] 没有占位符残留 `{name}` `{partner}` `{actor}` `{0}` `{1}` `@@`
- [ ] 没有和**任何其它包**重复的题面（转换包之间有全局去重断言）
- [ ] 动作型和提问型**都有**（`[Q]` 的包要两种题型都玩得到；纯动作包除外）
- [ ] 执行方池 ≥ 35
- [ ] 新写的任务和包里已有任务同一烈度
- [ ] `name` / `desc` 不含模式名
- [ ] `actionStates` / `conditionStates` 各 3 条且无禁止词
- [ ] 跑过 `npm run check`
